# Module: Internationalization (M1 plumbing)

Locale preference, **message keys** (not free-form server copy in APIs), and a **shared contract** for web + Flutter.

## Principles

- **Server** stores a **BCP 47-style** language tag on the user (`user_account.preferred_locale`); APIs return it as **`locale`** on `GET /api/v1/me`. No large message catalogs on the server in M1.
- **Clients** (Next.js, Flutter) own UI string tables keyed by **stable message keys** (e.g. `nav.dashboard`). Server rows that need labels (e.g. `nav_menu_item.label_key`) expose **keys only** — see [`navigation-menu.md`](./navigation-menu.md).
- **PII:** locale is not PII; do not put natural-language user content into “message key” fields.

## Data — `user_account.preferred_locale` (strict)

| Column | Type | Notes |
|--------|------|--------|
| `preferred_locale` | `VARCHAR(35)` | NOT NULL; normalized lowercase hyphen form (e.g. `en`, `nl`, `nl-sr`); default `en` |

## Supported locales (M1)

| Tag | Purpose |
|-----|---------|
| `en` | Default |
| `nl` | Dutch (generic) |
| `nl-sr` | Dutch — Suriname-first product alignment |

**Unsupported** tags on `PATCH` → **400** `UNSUPPORTED_LOCALE`.

## API

- **`GET /api/v1/me`** — includes **`locale`** (string) for the authenticated user in all tenant contexts.
- **`PATCH /api/v1/me/locale`** — body `{ "locale": "nl-sr" }`; CSRF required from browsers; **204** on success. Appends **`audit_event`** (`USER_LOCALE_CHANGED`, metadata `locale` tag only) — see [`audit.md`](./audit.md).

## Resolution order (product)

1. **Authenticated:** `user_account.preferred_locale` (returned on `/me`; updated via `PATCH`).
2. **Anonymous (future):** `Accept-Language` → closest supported match, else `en`.
3. **Flutter:** same `/me` + `PATCH` contract; bundle ARB / JSON catalogs client-side by key.

## Web

- Set `document.documentElement.lang` from the resolved locale on shell pages (`SetHtmlLang` in the tenant app layout tree under **`/app`**).
- Map `label_key` values to strings via client-side tables (see `frontend/src/messages/`).
- **Locale change:** on tenant web, the signed-in user switches language from the **header user menu** (calls **`PATCH /api/v1/me/locale`** via the BFF with CSRF). Open **Language** in the menu to reveal locale rows. The dashboard shows the active locale as read-only text (`me-locale-display`) for quick verification; Playwright uses **`user-menu-locale-toggle`** then **`user-menu-locale-*`** test ids.

## Proposed Schema Extension (requires PII review)

- Tenant-level default locale (`tenant_setting` key `locale.default`) — when specified, overrides display for anonymous tenant pages only; still out of scope until tenant portal UX is defined.
